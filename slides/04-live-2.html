Code First. Spec After.

The agents just shipped from Linear. No OpenSpec change. You can still land the truth — write the change that should have come first.

1
/opsx-explore · Read what landed
Point at the PR or the files. Map behavior before you invent a proposal.
2
/opsx-propose · Delta = what already shipped
Requirements and scenarios for the live behavior. Not a rebuild plan.
3
Review · then sync · archive
Catch wrong turns in the write-up. /opsx-sync + /opsx-archive fold into openspec/specs/. Skip apply if the code is already there.
Bonus only — do not run this live unless you have spare minutes. Point: specs grow from real changes; brownfield works the same way — explore the code, propose a delta that describes what exists, review, sync, archive. Apply only if something is still missing. Say “this is how you recover intent after a parallel PR.”
